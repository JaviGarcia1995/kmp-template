# Security Policy

## Supported Versions

Security fixes are applied to the latest version of the `main` branch. Older commits and projects
previously generated from this template are not maintained automatically.

Users of the template are responsible for keeping their generated projects and dependencies up to
date.

## Reporting a Vulnerability

Do not report security vulnerabilities through a public issue or discussion.

Use GitHub's private vulnerability reporting feature:

1. Open the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

Include:

- a description of the vulnerability and its impact;
- affected files, versions, or dependencies;
- reproduction steps or a proof of concept;
- any known mitigation or proposed fix;
- whether the issue affects the template itself or only generated projects.

You should receive an initial response within seven days. Confirmed vulnerabilities will be
assessed, fixed on `main`, and disclosed after a remediation is available when appropriate.

If private vulnerability reporting is unavailable, contact the repository owner privately through
their GitHub profile instead of opening a public issue.
